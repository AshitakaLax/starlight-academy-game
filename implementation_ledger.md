# Starlight Academy: Studio of Magic & Motion
## Revised Engineering Implementation Ledger

This ledger operationalizes the Revised Gameplay, Architecture & Engineering Implementation Plan. Acceptance criteria are required test outcomes, not merely descriptions of features. Status values begin as **Planned**.

**Release requirement:** All 10 chapters and 20 side quests ship in one self-contained HTML file. Multiple source files are allowed during development. Target browsers are desktop Chrome and Edge.

## Ledger-wide implementation rules

1. **No guessed gameplay rules:** if a chapter needs a special rule, put it in its chapter brief and tests before coding it.
2. **Configuration over scattered constants:** difficulty thresholds, rhythm windows, star thresholds, pet ability effects, economy values, and item prices live in centralized configuration.
3. **Content before implementation:** each chapter and side quest needs objectives, activity flow, generated content, correct-answer logic, hints, feedback, rewards, and tests.
4. **No hard failure:** a low score, missed rhythm cue, or use of hints cannot block main progression or erase rewards already earned.
5. **No pet decay:** no code path may reduce pet care or bond values due to elapsed time, inactivity, or app closure.
6. **Offline final build:** all player-facing runtime resources are embedded in the delivered HTML file.
7. **Test the release artifact:** final acceptance is based on the built standalone HTML in Chrome and Edge, not only the development environment.
